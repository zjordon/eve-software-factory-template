## 关键事实(已核实,实施依据)

- **Basic 鉴权不挡 webhook**:route auth 只守 4 组会话路由(session 创建/续话/cancel 族/stream,auth-and-route-protection.md 路由清单);`/eve/v1/github` 由 GitHub webhook HMAC 签名校验,不在 Basic 走查范围——无人值守与现行鉴权共存,零改造。
- **webhook 指向**:`https://<域名>/eve/v1/github`;事件订阅 5 项(issue_comment、pull_request_review_comment、issues、pull_request、check_suite),本仓通道钩子已按此接线,M1 建 App 时已订阅(待 T1c 复核)。
- **代理前缀两条都要透传且不可改写**:`/eve/` 与 `/.well-known/workflow/`(self-hosting.md;后者是 workflow 回调,断则 run 停摆)。
- **自建镜像有官方约定**:`agent/sandbox/Dockerfile` + `DockerSandbox.dockerfile()`(docker.mdx);现状 `createFactoryEnvironment` 用 `DockerSandbox.environment()`(默认镜像,node 底)。
- **examination-system 形态**:Python ≥3.12 uv 项目(`[tool.uv] package=false`),dev 依赖 pytest/ruff/playwright——镜像规格 git+uv+Chromium 正好对上;`FACTORY_SETUP_COMMAND=uv sync --extra dev` 是切换后配置(总方案 #8)。
- **FACTORY_SETUP_COMMAND 不能提前设**:local-factory-dev 无 pyproject,设了会在站点克隆后 setup 失败;该变量随 T3 切换才写入。
- **FACTORY_REPO 是构建期注入**(`defineInstructions` build 时解析):换仓库必须 `pnpm build` + pm2 restart,改 env 不重启无效。
- **quick tunnel 不适合常驻**:URL 每次启动随机变,只用于拉链路验收;命名隧道(URL 永久稳定)是 T3 切换的硬前置。
- **Docker 模板镜像会堆积**(现为 5 个 × ~600MB):`FACTORY_SANDBOX_CREATE_OPTIONS` 的快照保留只作用于 Vercel 后端,Docker 侧清理靠手工 `docker image prune`(运维口径,非阻塞)。
- **cloudflared 未装**(本机);域名未注册(用户并行办理)。

## 任务分解

### T1 隧道与 webhook 入口(改造点 #9)

- [ ] T1a 安装 cloudflared(官方 apt 仓库或独立二进制)
- [ ] T1b quick tunnel 拉链路:入站指向 `http://localhost:3000`;经隧道探 `/eve/v1/health` 200
- [ ] T1c GitHub App 设置:webhook URL 填 `https://<trycloudflare 域>/eve/v1/github`、secret 与 env 对齐、5 项事件订阅复核
- [ ] T1d App 设置页发 ping → 服务侧日志见到入口请求;错 secret 对照(签名校验拒收)——如果 GitHub 侧支持 redelivery 就再验一次投递重试
- [ ] T1e **中期验收**:local-factory-dev 开 issue 打 `factory` 标签 → 无人值守四站 → 草稿 PR(全程无人工介入,与 M2 remote 回合的区别就是入口从人变成 webhook)
- [ ] T1f 命名隧道:域名到位后 `cloudflared tunnel create` + DNS 绑定 + systemd 常驻(cloudflared service install 或自写单元);webhook URL 换永久域名;重启后 URL 不变、webhook 恒达验证

### T2 自建沙箱镜像(改造点 #8)

- [ ] `agent/sandbox/Dockerfile`:基底二选一实施时定——Playwright Python 官方镜像(Chromium+系统依赖齐备,体积约 2GB)打底 + git + uv;或 `python:3.12-slim` + git + uv + `playwright install --with-deps chromium`(体积小些、依赖自己扛)
- [ ] `createFactoryEnvironment` 换 `DockerSandbox.dockerfile()`(`FACTORY_SANDBOX_BACKEND` 的 Vercel 分支原样保留,云端形态不受影响)
- [ ] `pnpm validate` 0/0;重建后经 remote 会话在 local-factory-dev 跑一轮有人值守回合,确认新镜像容器内 git/uv 真实可用
- [ ] 运维注记:Docker 模板镜像 prune 口径(顺手清掉现存的 5 个旧模板)

### T3 仓库切换 examination-system(§5 协议;硬前置:T1f 命名隧道稳定)

- [ ] 用户动作:卸载云端 examiner App 在 examination-system 的安装(隔离铁律:任一时刻一个仓库只有一个工厂 App)
- [ ] 用户动作:把 zjordon-foreman-local App 安装到 examination-system(安装范围显式只选它)
- [ ] `.env.local`:`FACTORY_REPO=zjordon/examination-system` + `FACTORY_SETUP_COMMAND=uv sync --extra dev` → `pnpm build` → `pm2 restart`
- [ ] **终验(总方案 §7 M3 口径)**:examination-system issue 打 `factory` 标签 → 无人值守全流程(含沙箱内 uv sync/pytest 真跑)→ 草稿 PR;期间 Vercel 面板零新部署/调用
- [ ] 切回演练不执行(协议记录在案:反向操作分钟级可逆)

### T4 收口

- [ ] 执行记录回写本文件 + `docs/architecture.md`(webhook 入口一节按实测更新:隧道形态、事件流、签名校验)
- [ ] 评审循环(review-loop)对 M3 提交批次照 M1/M2 惯例跑一轮

## 风险与应对

| 风险 | 症状 | 应对 |
|------|------|------|
| trycloudflare/Cloudflare 边缘在国内网络不稳 | quick tunnel 起不来或 webhook 超时 | 本机直连国际端点已通(github/bigmodel 200),先实测;真不可达则命名隧道同源受限,启动轮询适配器备案(纯出站,零入口) |
| quick tunnel URL 重启即变 | webhook 静默断链 | 设计如此:quick tunnel 只用于 T1b-T1e 拉链路;T3 前必须完成命名隧道 |
| Playwright 镜像体积大/构建慢 | 磁盘与首次构建耗时 | 根卷 44G 余量充足;构建一次入库后续增量 |
| uv sync 首站在沙箱内下载依赖慢 | 首个 examination-system 回合偏长 | 接受(依赖随仓库演进,不预烘);记录实测时长 |
| App 安装范围误配 | 串线到其他仓库 | 安装时显式只选 examination-system;切换后立刻打标签验证归属 |
| webhook secret 不匹配 | ping 通但事件 401/403 | T1c 用 env 同源值粘贴;T1d 错 secret 对照提前暴露 |
| 隧道进程无守护 | cloudflared 挂了 webhook 断 | systemd 常驻 + Restart=always;health 拨测纳入 M4 监控 |

## 预估

总方案口径 1-2 天:T1 半天(链路为主,域名注册等待并行),T2 半天(镜像构建与验证),T3 半时(切换与终验),T4 并入收口;实际节奏受域名注册与 Cloudflare 生效时间影响。
