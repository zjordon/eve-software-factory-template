### T2 自建 GitHub App(BYO)

## 执行记录(2026-10-13)

T1-T6 一次通过;验收清单全绿(评测项见文末备注)。与计划的偏差与实测发现,按条留档:

### 改动面比计划大:13 个文件,不是 2 个

计划 T3 只列了 `channels/github.ts` + `credentials.ts`,实测必须连带动 11 个文件(commit `0e10da9`,+509/-174)。根因是三处计划未覆盖的 Vercel 耦合:

- **站点与根沙箱环境本身就是 `VercelSandbox.environment()`**(`repo-sandbox.ts` / `agent/sandbox.ts`)——本机无 Vercel 凭据连会话都开不了。新增 `FACTORY_SANDBOX_BACKEND=vercel|docker` 开关(默认 vercel,云端行为不变),双形态收敛于此。
- **git 凭据注入是防火墙专属**:`setNetworkPolicy(brokerPolicy)` 在 Docker 上不可用(仅 allow-all/deny-all),且联合类型会直接编译报错。新增 `armGitCredentials`/`disarmGitCredentials` 一对函数(位于 `git-remote.ts`):Vercel 走原防火墙 header 注入;Docker 走文件型 git credential helper(令牌经 `writeTextFile` 文件 I/O 写入,不经命令行,finally 里删文件 + 清配置)——这是总方案 #7 的最小前置版,四个 git 场景(factoryInit 克隆 / push_branch / 两处 checkout_branch)各改两行。
- **扩展也是 Connect 耦合**:`extensions/github.ts` 的 `connector:` 换成 `token: mintInstallationToken`(扩展原生支持)。

另外两项顺手动:`bot-name.ts` 去 Connect(名字从 `GITHUB_APP_SLUG` env 解析,async 契约保留);`bootstrap-diagnostics.ts` 消息措辞改为 App 通用。

### Blob 本地后端从 M3 提前(总方案 #6 的最小版)

M1 流水线的偏好/工厂大脑/工件交接全走 `@vercel/blob`,本机没有 OIDC 凭据,运行时必挂。新增 `FACTORY_BLOB_BACKEND=vercel|local` 开关:local 后端落盘 `FACTORY_DATA_DIR`(默认 `.eve/blob-data`),只换 `blob.ts` 三个文档助手的底层(注册表与守卫原样),键做目录逃逸防御。返回形状仅消费 `pathname`,两后端兼容。

### T2 实测(App 创建的 UI 变化)

- App ID **5293439**、App slug `zjordon-foreman-local`、Installation ID **170788094**(安装页 URL 尾号)。PEM 生成入口在新 UI 的 **Credentials → Key pairs → New key**(不是老表单页底的按钮)。
- 取消勾选 Webhook **Active** 后,URL 的必填即解除,可整段留空——比计划预案(占位 URL)更干净。
- 权限区是逐行 "Access" 弹出菜单(非原生 select),选项文案是 **"Read and write"**(不是 "Read & write");事件订阅区在设完权限后才出现相关选项,按 checkbox value 精确勾选 5 项。
- 安装范围复核:Only select repositories + 仅 `local-factory-dev` 1 仓库(隔离铁律)。
- 令牌铸造冒烟:标准 node 脚本独立复现 JWT→access_tokens,1h 令牌、12 项权限、测试仓库可见(HTTP 200)。

### T5/T6 实测

- `pnpm dev` 起 HTTP 服务(127.0.0.1:2000),**非 TTY 环境自动禁用交互 UI**;首次运行构建 7 个 docker 模板镜像(root + 6 站点,约 30 秒一次性成本),之后站点会话按模板秒级拉起。
- `eve info` **不加载** `.env.local`(只有 dev 命令加载,`DEVELOPMENT_ENV_FILE_NAMES` 优先级 `.env.development.local` > `.env.local` > `.env.development` > `.env`),CI/脚本里跑 validate 或 eval 需先注入 env。
- T6 任务 "add a hello.txt at repo root containing: hello world" 全程约 4 分钟:分支 `factory/chore-hello-txt`、提交者 `zjordon-foreman-local[bot]`、**PR #1 草稿**(作者 `app/zjordon-foreman-local`,What/Why/Approach 结构完整)。评审站独立复核在日志可见(`od -c` 逐字节验证、README 未动检查);其间一条命令 exit 127 后自行换路恢复。
- 审批卡如预期弹出(本地 principal 不受信),人工批准后 PR 落地——信任模型在本地形态下原样成立。
- 已知噪音(非阻塞):SDK 对 `glm-5.3` 不识别,`maxOutputTokens` 被限 4096 的兼容警告每站必刷,属 fork 既有行为,M2+ 可在模型配置里显式设值消音。
- 本任务太小未触发长文档工件(blob-data 为空);Blob 本地后端的落盘实证留给下一个真实需求。
