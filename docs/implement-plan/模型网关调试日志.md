# 模型网关调试日志(issue #9,2026-11-15)

## 动机

examination-system issue #37 的分析站(analyst,glm-5.3)连续 5 次同型失败,加上一次探针复现(给停放子会话发续推消息,3.5 分钟后再死),全部签名为 `[eve:harness.tool-loop] model call failed — parking session` 且 `details: {}` 全空——错误无 HTTP 状态码、无网关错误体、不在框架语义错误知识库内,归属兜底类,拿不到框架的 3 次瞬时错误重试预算。

已排除:网关随机抖动(可按需复现;researcher/classifier 走 **glm-5.3-flash** 长跑存活)、毒历史(死亡前多次调用成功)、输出截断(失败时输出仅 1-1.5K tokens)、上下文溢出(1M 窗口实际 13 万)、网络直连(国内端点探测稳定)。

工作假设:GLM 全量模型在**工具密集流式响应**下偶发协议级缺陷(如流末尾晚到/重复的 tool_use 块),AI SDK 在后续请求构造时抛无 HTTP 信号的客户端错误。判定需要失败瞬间的网关原始行为,而现有观测面(run 记录的结构性错误码 + 停车日志)都不携带。

## 设计

`agent/lib/models.ts` 的 `createAnthropic({ fetch })` 注入包装 fetch(`zhipu-fetch:` 前缀,**failure-only,常开**)。除日志外传输字节级等价。只进 pm2 日志,不进 `.eve/run-records/`(metadata-only 政策不动):

- **传输层失败**(fetch reject):耗时 + 路径 + 请求体大小 + 错误对象(含 cause)
- **非 2xx 响应**:状态码 + 耗时 + 响应体前 500 字符(重建 Response 透传,剔除 content-length/content-encoding 头)
- **SSE 流异常终止**(没见到 `message_stop`/`[DONE]`):总字节数、**是否出现过 tool_use 块**(缺陷签名)、事件类型序列(相邻去重,末 12 个)
- **消费端取消**(SDK abort):字节数 + 最后事件类型,与异常终止区分标注
- 正常调用零输出

## 排障读法(运维手册交叉引用)

下次站点连败时,按时间对齐 `pm2 logs foreman-local` 里 `zhipu-fetch:` 行与停车日志:

| 看到 | 含义 |
|---|---|
| `stream ended without a terminal event ... tool_use seen: true` | 网关在 tool_use 流中途断流——协议级缺陷实锤 |
| `stream cancelled by consumer` 紧跟下一调用 `transport failed` | 传输层问题 |
| `HTTP 5xx/429` + 响应体 | 网关显式错误(这类框架会自动重试,通常不致死) |
| 停车日志有错但零 `zhipu-fetch:` 行 | 错误在请求构造层(如 AI_MissingToolResultsError 的孤儿 tool_use 假设),上一发响应的流形态看前一条日志 |
