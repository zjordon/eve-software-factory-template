## 关键事实(已核实)

- **事件面完整**:`defineInstrumentation` 支持全生命周期事件——`channel.delivery.*`(webhook 进站)、`session.started/waiting/completed/failed`、`turn.*`、`action.*`(四站调度:run_classifier 等 + push_branch + 开 PR 都走 action)、`model.call.*`(含 token usage 与 finish reason)、`tool.call.*`、`input.requested/resolved`(审批卡)、`memory.operation.*`。文档:instrumentation.mdx。
- **重放安全**:start 与终态事件共享 idempotencyKey,`ctx.state` 跨 durable 挂起存活——运行记录必须按 idempotencyKey **upsert**,不能盲目 append(断电恢复后事件会重放,M4 已实测重启是常态)。
- **内容捕获天花板**:tracePolicy 按 audience/environment 控制 inputs/outputs,production + private 默认只记元数据——默认口径即满足"元数据够画时间线",无内容泄露面。
- **自定义 channel 可声明任意路由**(custom.mdx `routes:`),面板可由工厂自身服务:零新增进程、零新增隧道规则、天然与主服务同生共死。
- **认证是通道自治的**(M3 实测):eve 通道的 Basic 只作用于 /eve/v1,github webhook 通道走独立验签——**面板通道必须自带 auth**,复用 M2 的 basicUser(lib 化抽取),不用 none()。
- **useEveAgent/Client SDK 有 `resume(sessionId)`**:回放并实时跟随在途轮的事件流;`events` 暴露原始线事件;auth 可传 headers。参照物:Vercel Agent Runs(Hobby Beta)= 官方会话浏览器,先看交互再定面板信息密度。
- **待核实两项(2026-11-12 落定,对照 dist 类型与实测)**:① **instrumentation 事件不带 issue 号**——`session.started` 只有 channelKind/channelType/title,delivery 事件只有 deliveryId;映射改在 **github 通道事件层**:continuation token 格式为 `repo:<repositoryId>:issue:<n>` / `repo:<id>:pull:<n>` / `repo:<id>:pull:<n>:review-comment:<cid>`(dist 实现核实),空闲键 handler 解析它 + 读 `intakeIssue` auth 槽位。约束:`githubChannel({ events })` 的 handler **替换**内置行为,`turn.started`/`message.completed`/`input.requested`/`session.failed`/`turn.failed` 是内置的不能碰,只能用 `actions.requested`/`action.result`/`session.waiting`/`session.completed`/`turn.completed` 等空闲键。② **不需要 Client SDK 跨连接 resume**:custom channel 路由可服务端 `attachSession(id).getEventStream({ startIndex: -1 })` 代理 NDJSON,无权限语义问题;降级路径(10 秒轮询)照草案内置。
- **运行环境事实**:`.eve/` 下已有 .workflow-data 与 blob-data(备份脚本口径),新增 `.eve/run-records/` 目录归属一致,是否纳入备份在 T6 决定;pm2 重启守 M4 后新规矩(干净环境 delete + start + save);ocr 在 nvm v25 全局 bin(绝对路径调用),工厂链路钉 v24。

**端到端实测追加修复(#33 实跑,用户报障,2026-11-12 晚)**:详情页实时流报 HTTP 502 降级轮询。根因:`attachSession().getEventStream()` 产出**已解析的事件对象流**(类型 `ReadableStream<MessageStreamEvent>`),直接交给 `new Response()` 时服务层无法把对象写入 socket → 空回复断连(本机 curl 实证"Empty reply from server";隧道侧 Cloudflare 表现为 502)——custom.mdx 的直传示例对运行时形态有误导。修复:路由内 `pipeThrough(TransformStream)` 把每个事件编码为一行 NDJSON(`JSON.stringify + \n`,与 eve 通道自家流路由同款框架习惯)。教训入档:**部署前本地流测试当时被 `| head` 管道掩码了 curl 退出码,误判"流关闭正常"——流式端点的测试必须看响应头 + 字节数,不能只看退出码**。

**同晚三改(用户三报"TypeError: network error 降级轮询")**:站点长工具期间流静默 ~100 秒后被掐,根/子流同时断——Cloudflare 边缘对无字节流的空闲切断(本地代理工具同类),服务端心跳 + 客户端重连各修一半:流路由每 25 秒发一行空 NDJSON 心跳(读者跳过空行,断连后首个失败 enqueue 即停表);客户端流中断先重连(3 次、间隔 5 秒)再降级轮询,子会话流网络错重连 2 次(正常结束不重连,防终态空转)。实测本机/隧道静默窗口心跳空行如期到达,浏览器连接跨静默期稳定。
