## 关键事实(已核实)

- **事件面完整**:`defineInstrumentation` 支持全生命周期事件——`channel.delivery.*`(webhook 进站)、`session.started/waiting/completed/failed`、`turn.*`、`action.*`(四站调度:run_classifier 等 + push_branch + 开 PR 都走 action)、`model.call.*`(含 token usage 与 finish reason)、`tool.call.*`、`input.requested/resolved`(审批卡)、`memory.operation.*`。文档:instrumentation.mdx。
- **重放安全**:start 与终态事件共享 idempotencyKey,`ctx.state` 跨 durable 挂起存活——运行记录必须按 idempotencyKey **upsert**,不能盲目 append(断电恢复后事件会重放,M4 已实测重启是常态)。
- **内容捕获天花板**:tracePolicy 按 audience/environment 控制 inputs/outputs,production + private 默认只记元数据——默认口径即满足"元数据够画时间线",无内容泄露面。
- **自定义 channel 可声明任意路由**(custom.mdx `routes:`),面板可由工厂自身服务:零新增进程、零新增隧道规则、天然与主服务同生共死。
- **认证是通道自治的**(M3 实测):eve 通道的 Basic 只作用于 /eve/v1,github webhook 通道走独立验签——**面板通道必须自带 auth**,复用 M2 的 basicUser(lib 化抽取),不用 none()。
- **useEveAgent/Client SDK 有 `resume(sessionId)`**:回放并实时跟随在途轮的事件流;`events` 暴露原始线事件;auth 可传 headers。参照物:Vercel Agent Runs(Hobby Beta)= 官方会话浏览器,先看交互再定面板信息密度。
- **待核实两项(开工首日,dev TUI 实地打印事件负载)**:① github channel 的 session 事件是否携带 issue 编号/仓库名(决定 issue↔run 映射在哪一层实现;若无,从 channel.delivery 事件的 delivery 元数据取);② 对"非本连接创建的 session"做流式 resume 的权限语义。
- **运行环境事实**:`.eve/` 下已有 .workflow-data 与 blob-data(备份脚本口径),新增 `.eve/run-records/` 目录归属一致,是否纳入备份在 T6 决定;pm2 重启守 M4 后新规矩(干净环境 delete + start + save);ocr 在 nvm v25 全局 bin(绝对路径调用),工厂链路钉 v24。

## 风险与应对

| 风险 | 症状 | 应对 |
|------|------|------|
| session 事件缺 issue 映射字段 | 记录里 issue 列为空 | 从 channel.delivery 元数据取;再不行在 github 通道 onIssue 处将 issue 号写入 session attributes(小改动,过评审) |
| 流式 resume 语义不符 | 详情页接不上在途轮 | 降级轮询 run-record(T3 已内置降级路径) |
| 事件量过大撑爆记录 | run-records 膨胀 | model.call 只聚合计数与 token,不逐条落;30 天保留 + 每日清理 |
| 面板通道拖累主服务 | dashboard 路由异常影响 eve | 自定义通道失败隔离(eve 文档口径:handler 各自独立);面板路由最坏 404,主链路不受累 |
| pm2 重启踩回环境缓存坑 | 新 instrumentation 不生效 | 守 M4 新规矩:干净 shell + env 剥代理 + delete/start/save |
| OTel 栈复杂度超预期 | T5 拖工期 | 触发条款即记录放弃,主线不受阻 |
