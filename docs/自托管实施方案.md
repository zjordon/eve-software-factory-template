# 本地自托管实施方案:eve Software Factory 脱离 Vercel

> 关联 issue:[#1](https://github.com/zjordon/eve-software-factory-template/issues/1)
> 生成时间:2026-10-11 | 状态:方案评审中(未开工)
> 评估依据:node_modules/eve/docs 官方文档原文查证(self-hosting.md、channels/github.mdx、sandbox/docker.mdx、sandbox/just-bash.mdx),非推测。

## 1. 背景与目标

在自有机器上运行工厂的**完整无人值守流水线**:GitHub issue 打 `factory` 标签 → 四站(分类/分析/实现/评审)执行 → 草稿 PR。不依赖 Vercel 的托管运行时,也不依赖 Vercel Connect 的凭据与事件转发。

约束:云端工厂 A/B 并行保留,本地版先服务 `zjordon/examination-system`,稳定后再决定去留。

## 2. 可行性结论(评估摘要)

| 判断 | 依据 |
|------|------|
| eve 官方支持自托管:`eve build` + `eve start`(Nitro Node 服务),工作流状态默认本地 `.eve/.workflow-data` | guides/deployment/self-hosting.md |
| GitHub 通道官方支持自带 App(BYO):三环境变量凭据,App JWT 换安装 token、webhook 签名校验均为 eve 原生能力;模板的 onIssue/onComment/onCheckSuite 钩子原样保留 | channels/github.mdx "Bring your own GitHub App" |
| 模型层零改动:fork 已是智谱直连(@ai-sdk/anthropic),恰是自托管推荐姿势 | 本仓库 agent/lib/models.ts |
| Docker 沙箱 networkPolicy **仅支持 allow-all / deny-all**,无请求头注入 → 站点 git 的"token 防火墙注入"模型必须降级改造 | sandbox/docker.mdx |
| 通道自带的 sandbox checkout 在本地后端被跳过(防火墙能力仅 Vercel)——本模板不受影响,站点自己 clone | channels/github.mdx "Sandbox checkout" |

三个知情的缺口(决策已记录,见 §6):凭据注入降级、公网 HTTPS 入口、7x24 与本机绑定。

## 4. 分阶段实施

### M1 本机有人值守(~1 天)

**目标**:TUI 里派活,四站流水线全本地跑,产出真实草稿 PR。零公网、零隧道。

1. 手建 GitHub App(上表 #2):名字建议 `zjordon-foreman-local`;M1 阶段 webhook URL 可留空(TUI 派活不需要事件);生成私钥(PEM)存 `.env.local` 引用路径
2. `agent/channels/github.ts` 换 BYO 凭据(上表 #1);`.env.local` 加三变量 + 智谱 key(已有)
3. `pnpm validate` 通过;`pnpm dev` 起本地 TUI
4. 验证:派一个 hello 级任务到**专用测试仓库**(见 §5 仓库切换协议),观察四站 + 本地沙箱 clone/push + 草稿 PR
5. 风险点:本地 DefaultSandbox 的选择顺序(Docker 优先,需 Docker Desktop 就绪);`pnpm eval --tag fast` 跑通,needs-connect 用例按上表 #10 处理

### M2 常驻服务(~1 天)

**目标**:WSL2 内常驻 Node 服务,开机自启,局域网可访问。

1. 剥离 Linear(上表 #3),validate 全绿
2. 路由鉴权换 Basic(上表 #4)
3. WSL2 内:`eve build && PORT=3000 eve start`,pm2 守护 + 开机自启
4. 验证:`curl localhost:3000/eve/v1/health` 200;`eve remote connect --url http://localhost:3000` 从 Windows 侧连入,完成一次真实回合;pm2 重启后状态不丢(`.eve/.workflow-data` 持久化)

### M3 无人值守(~1-2 天)

**目标**:issue 打标签 → 家里机器自动出 PR。

1. cloudflared 命名隧道 → 稳定 HTTPS 域名(上表 #9;选轮询适配器则另立设计)
2. GitHub App webhook URL 指向 `https://<域名>/eve/v1/github`,secret 对齐;事件订阅核对 5 项
3. Blob 本地文件后端(上表 #6);云端已有工厂大脑/偏好数据按需一次性导出导入(可选项,默认从空开始)
4. 站点 git 凭据适配 + env 开关双形态(上表 #7),工厂/云端行为各归各位
5. 自建沙箱镜像(上表 #8),e2e 在流水线内真跑(独有收益)
6. **执行仓库切换协议**(§5):先在测试仓库全链路验收,再切 examination-system
7. 验收:examination-system 打标签 → 无人值守全流程 → 草稿 PR,全程无 Vercel 参与

### M4 加固(~1 天)

1. examination-system 配 GitHub Actions(ruff + pytest + e2e)→ 故意推红 → 验证红 CI 修复环本地接手(factory/* 前缀已强约束)
2. 监控:health 端点外部拨测 + pm2 日志轮转;`.eve/.workflow-data` 与 `FACTORY_DATA_DIR` 纳入备份
3. 断电/断网恢复演练:重启后未完成 run 的续跑行为确认
4. 文档回写:本文件标记完成态,操作手册沉淀到 out/

## 5. 仓库切换协议(防串线,必读)

**两个 App 装在同一个仓库 = 两套流水线抢同一个 issue**(云端 examiner 与本地 App 的事件各自转发,互不知情)。协议:

1. M1/M3 验收期:本地 App 只安装在**专用测试仓库**(建议新建 `zjordon/local-factory-dev`,或复用 factory-playground 但注意云端 foreman 也装在那 → 新建更干净)
2. 切换 examination-system 到本地版:先卸载云端 `zjordon-examiner` 在该仓库的安装 → 再安装本地 App → 打标签验证
3. 切回云端:反向执行,分钟级、可逆
4. 该协议是隔离铁律的延伸:**任一时刻,一个仓库只有一个工厂 App**

## 6. 风险与决策记录

| 风险/决策 | 说明 | 处置 |
|------|------|------|
| 凭据注入降级 | token 由"永不进沙箱"变为"短暂进入、用后即焚" | 缓解:1 小时短期 token + finally 清除 + Docker 隔离;个人自用接受;记录在案 |
| 公网入口 | 家用网络 + 隧道稳定性 | 命名隧道 + 自有域名;不可接受时切轮询适配器(纯出站) |
| 7x24 绑定 | 机器关机流水线停 | 接受(个人场景);云端 B 保留期间可兜底 |
| 双形态维护 | BYO/Connect 两套凭据、docker/vercel 两种沙箱后端 | env 开关收敛分叉点(#1 #7),避免 if 散落 |
| Windows 复杂度 | 原生 Windows 跑常驻服务 + Docker | 主体进 WSL2;Windows 侧只做开发与浏览 |
| evals 回归 | needs-connect 用例在 BYO 下失效 | M1 标记处置方案 |
| eve 升级兼容 | 自托管接口随版本演进(当前 0.67) | 升级前跑 self-hosting 文档 diff 检查 |

## 7. 验收标准

- **M1**:TUI 派真实任务 → 四站完成 → 测试仓库出现草稿 PR;本地沙箱内 clone/uv/pytest 全部真实执行
- **M2**:pm2 托管 + 重启自愈;health 200;Windows 侧 remote connect 可用
- **M3**:examination-system issue 打 `factory` 标签(本地 App)→ 无人值守草稿 PR;期间 Vercel 面板无任何新部署/调用;沙箱内 e2e 真跑
- **M4**:红 CI 自动修复环闭环;备份与恢复演练通过

## 8. 最终环境变量清单(自托管形态)

```
FACTORY_REPO=zjordon/examination-system
FACTORY_LABEL=factory
FACTORY_SETUP_COMMAND=uv sync --extra dev        # 镜像预装 uv 后简化
GITHUB_APP_ID=...                                 # 自建 App
GITHUB_APP_PRIVATE_KEY=<PEM 路径或值>
GITHUB_WEBHOOK_SECRET=...
ZHIPU_API_KEY=...                                 # 已有
FACTORY_SANDBOX_BACKEND=docker                    # vercel|docker 双形态开关
FACTORY_DATA_DIR=.eve/blob-data                   # Blob 本地后端
# 路由 Basic 凭据(名称以 auth 文档为准)
```

不再需要:`LINEAR_CONNECTOR`、`GITHUB_CONNECTOR`、`BLOB_STORE_ID`、`BLOB_WEBHOOK_PUBLIC_KEY`、`VERCEL_OIDC_TOKEN`。

## 9. 与云端工厂的关系

云端 A/B 冻结在当前能力(含 factory/ 前缀强约束,187bc46),不再从改造后的 main 部署,避免双形态意外混部;本地版经 §5 协议接管 examination-system 后,云端 B 可保留观察一个迭代周期再退役。fork 的 main 成为自托管主线,云端形态仅通过 env 开关兼容。
