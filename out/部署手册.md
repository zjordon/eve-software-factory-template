# eve Software Factory 部署手册(手动 B 路线·智谱 GLM 版)

> 生成时间: 2026-10-09
> 本手册源自一次真实的从零部署实录,每一步都经过实战验证;所有"坑"栏都是实际踩过并解决的问题。
> 适用场景:不走 README 的 Deploy 按钮,手动搭建全部基础设施,并接入智谱 GLM Coding Plan 作为模型供应商。

## 0. 前提条件

| 依赖 | 说明 |
|------|------|
| Node.js 24.x | `node --version` 确认 |
| pnpm | 包管理器(仓库带 pnpm-lock) |
| gh CLI | GitHub 命令行,`gh auth status` 确认已登录(建 scratch 仓库用) |
| Vercel 账号 | vercel.com,免费 Hobby 即可 |
| GitHub 账号 | 已有;准备一个 scratch 仓库作为工厂的施工对象(FACTORY_REPO) |
| Linear 账号 | linear.app 免费注册一个 workspace;`LINEAR_CONNECTOR` 是模块加载期必需,没有它连构建都过不了 |
| 智谱 GLM Coding Plan | open.bigmodel.cn(国内)或 z.ai(国际),拿到 API key |

**先建 scratch 仓库**(工厂将克隆它、推分支、开 PR,别用生产仓库):

```powershell
gh repo create <你的用户名>/factory-playground --public --add-readme
```

## 1. 安装 Vercel CLI 并登录

```powershell
npm install -g vercel    # 全局安装;验证: vercel --version
vercel login             # 浏览器授权
```

> 坑 ①:`vercel` 不是命令 → CLI 未安装。它和 pnpm 一样走 npm 全局分发,与项目本身无关。

## 2. 创建 Vercel 项目并 link

在项目根目录:

```powershell
vercel link
```

没有已有项目时它会**新建一个**(以目录/仓库名命名)并写 `.vercel/project.json`。

> 坑 ②:link 末尾报 `Failed to connect <owner>/<repo> to project` → 是 git 集成那一步失败(Vercel GitHub App 看不到你的仓库),**项目本身已建好**。B 路线用 CLI 部署,不依赖 git 集成,此错可忽略;若想要 push 自动部署,去 github.com/settings/installations 给 Vercel App 补装仓库后 `vercel git connect`。

## 3. 创建 Blob 存储

```powershell
vercel storage create eve-factory-blob --type blob --access public
vercel storage connect eve-factory-blob --yes
```

产出 OIDC 凭据模式(与应用架构要求一致),自动注入 `BLOB_STORE_ID` 等变量到三个环境。`vercel storage status` 核验。

## 4. 环境变量(含 BOM 大坑)

需要的变量(全部三环境:production / preview / development):

| 变量 | 值示例 |
|------|------|
| `FACTORY_REPO` | `<你的用户名>/factory-playground` |
| `GITHUB_CONNECTOR` | `github/github`(第 5 步产出) |
| `LINEAR_CONNECTOR` | `linear/linear`(第 6 步产出) |
| `ZHIPU_API_KEY` | 你的智谱 key(第 9 步,建议先只配本地) |

> 坑 ③(最隐蔽):**PowerShell 5.1 管道给 `vercel env add` 传值会在开头塞 UTF-8 BOM**。存进去的值实际是 `\uFEFF...`,会过不了工厂模块加载期的 `FACTORY_REPO` 正则校验,且表面完全看不出来。
> **正确姿势(文件重定向,绕开 PS 管道)**:

```powershell
[System.IO.File]::WriteAllText("$env:TEMP\v.txt", '你的用户名/factory-playground')
cmd /c "vercel env add FACTORY_REPO production --type config < %TEMP%\v.txt"
# preview、development 各重复一次;每个环境一条命令,一次只能加一个环境
```

验证:`vercel env pull .env.local --yes` 后检查行内容与长度(无 BOM、无尾部 `\r`)。

> 坑 ④:`pnpm validate` 里的 `eve info` **不读 `.env.local`**(那是 `pnpm dev` 的行为),模块评估直接读 shell 环境。validate 前注入:

```powershell
$env:FACTORY_REPO='你的用户名/factory-playground'; $env:GITHUB_CONNECTOR='github/github'; $env:LINEAR_CONNECTOR='linear/linear'; pnpm validate
```

## 5. GitHub 连接器

```powershell
vercel connect create github --name github --triggers --trigger-path /eve/v1/github
```

浏览器引导你创建 GitHub App。要点:

- **App 名字**(如 `zjordon-foreman`)会成为机器人的 `@提及` 名和 `<slug>[bot]` 身份,起个自己会喊的名字
- 授权页选择仓库范围时,**把 scratch 仓库勾进去**(或 All repositories)
- 完成后 `vercel connect list` 拿 UID(形如 `github/github`),然后:

```powershell
vercel connect attach github/github --triggers --trigger-path /eve/v1/github --yes
```

再用第 4 步的文件重定向法把 `GITHUB_CONNECTOR=github/github` 写入三环境。

> 坑 ⑤:**不要在 Git Bash 跑这条命令**(`!` 前缀即 Git Bash)。MSYS 会把以 `/` 开头的参数当 POSIX 路径转换,`/eve/v1/github` 会变成 `D:/soft/Git/eve/v1/github` 之类,webhook 全部转发到错误路径。在 PowerShell 跑则天然免疫;必须在 bash 跑就加前缀 `MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'`。若已中招,在连接器管理页删除错误路径的 trigger 目的地即可(见第 10 步的页面路径)。

> 坑 ⑥(**必查,事件订阅缺失**):引导式创建的 GitHub App 默认可能只订阅了 "Pull request" 一个事件。这样 GitHub 根本不会发送 issue 事件——症状是:打标签毫无反应,GitHub App 的 Advanced 投递记录里没有 `issues` 条目。
> **修复**:github.com/settings/apps → 你的 App → **Permissions & events** → Subscribe to events 勾上 **Issues / Issue comment / Pull request / Pull request review comment / Check suite** → Save(立即生效,无需重装)。这也解释了"本地跑通≠事件正常":公开仓库的克隆不需要 App 权限,推送成功只证明安装和写权限,不证明事件订阅。

## 6. Linear 连接器

```powershell
vercel connect create linear --name linear --triggers --trigger-path /eve/v1/linear
```

- 连接方式选 **OAuth application**(托管路径,一次浏览器授权,免管理 client secret)
- > 坑 ⑦:OAuth 应用名**不能含 "Linear" 字样**(Linear 的品牌保护规则),报 `OAuth application name cannot use the word Linear` 就换个名字
- 若中途报 `creation_failed`,先 `vercel connect list` 看看——大概率服务端其实已落盘,补 attach + 环境变量即可:

```powershell
vercel connect attach linear/linear --triggers --trigger-path /eve/v1/linear --yes
# 再用文件重定向法写入 LINEAR_CONNECTOR=linear/linear 到三环境
```

## 7. 接入智谱 GLM(替换默认的 Vercel AI Gateway 模型)

```powershell
pnpm add @ai-sdk/anthropic
```

改 `agent/lib/models.ts`(完整替换):

```ts
import { createAnthropic } from "@ai-sdk/anthropic";

const zhipu = createAnthropic({
  apiKey: process.env.ZHIPU_API_KEY,
  baseURL:
    process.env.ZHIPU_BASE_URL ?? "https://open.bigmodel.cn/api/anthropic/v1",
});

export const MODELS = {
  analyst: zhipu("glm-5.3"),
  classifier: zhipu("glm-5.3-flash"),
  implementer: zhipu("glm-5.3"),
  orchestrator: zhipu("glm-5.3"),
  researcher: zhipu("glm-5.3-flash"),
  reviewer: zhipu("glm-5.3"),
} as const;

export type FactoryAgent = keyof typeof MODELS;

export const MODEL_CONTEXT_WINDOW_TOKENS: Record<FactoryAgent, number> = {
  analyst: 1_000_000,
  classifier: 200_000,
  implementer: 1_000_000,
  orchestrator: 1_000_000,
  researcher: 200_000,
  reviewer: 1_000_000,
};
```

再给**全部 6 个** `agent.ts`(根 + 5 个站点)的 `defineAgent` 加一行:

```ts
modelContextWindowTokens: MODEL_CONTEXT_WINDOW_TOKENS.<对应角色>,
```

(import 相应调整;跑 `pnpm fix` 自动整理格式。)

> 坑 ⑧(**/v1 路径**):`@ai-sdk/anthropic` v4 的约定是 baseURL **自带版本段**、只追加 `/messages`;而 Claude Code / Anthropic 官方 SDK 是 base 不带 `/v1`、客户端拼 `/v1/messages`。把 Claude Code 的配置地址原样抄来会打到 `.../api/anthropic/messages`,智谱网关对该路径回 **HTTP 200 + 空流**,症状是 `MODEL_CALL_FAILED: The model did not return a response`(底层 `AI_NoOutputGeneratedError`)。**baseURL 必须以 `/v1` 结尾**。国际版套餐设 `ZHIPU_BASE_URL=https://api.z.ai/api/anthropic/v1`。

> 坑 ⑨(**上下文窗口元数据**):模型不在 Vercel AI Gateway 目录里,eve 编译压缩(compaction)配置时查不到窗口元数据,报 `Cannot compile agent compaction ... does not have known AI Gateway context window metadata`。解法就是上面的 `modelContextWindowTokens`(官方逃生舱字段,设了即跳过目录查询)。GLM-5.3 官方规格 1M 上下文 / 128K 输出;flash 档保守填 200K。

> 模型 id 可按套餐实际供应调整(改 `MODELS` 里的字符串即可);窗口数与 id 保持同步。注意:单一供应商意味着原模板"implementer 与 reviewer 异厂商互审"的设计取舍掉了。

## 8. 本地验证与试跑

```powershell
# 1. .env.local 补模型 key(自己编辑,密钥永不进对话/仓库)
#    ZHIPU_API_KEY=你的key
#    (国际版再加 ZHIPU_BASE_URL=https://api.z.ai/api/anthropic/v1)

# 2. 全量校验(记得先注入第 4 步的三个 shell 变量)
pnpm validate          # 0 errors / 0 warnings 才继续

# 3. 拉全云端环境
vercel env pull .env.local --yes

# 4. 启动 TUI
pnpm dev
```

- **不需要 `/login`**:models.ts 里的自定义模型自带 env 凭证,eve 走"显式环境凭证"路径;`/login` 只服务于网关字符串/官方 helper 那五种内置连接
- 启动时的 `DEP0190 DeprecationWarning`(child_process + shell:true)是工具链内部旧写法的弃用提醒,**无害,无视**
- TUI 里直接派个小任务(如 "add a hello.txt"),观察四站流水线;本地 principal 不受信,涉及 GitHub 写操作会弹审批卡,这是设计行为

## 9. 生产部署

```powershell
# 1. 模型 key 配到生产环境(交互输入,密钥自己填)
vercel env add ZHIPU_API_KEY production

# 2. 部署(eve 是项目本地依赖,用 pnpm exec 调;全程无需 git 集成)
$env:FACTORY_REPO='...'; $env:GITHUB_CONNECTOR='github/github'; $env:LINEAR_CONNECTOR='linear/linear'
pnpm exec eve deploy
```

部署产出生产 URL(`https://<项目名>-<团队名>.vercel.app`)。安全性检查:`.vercelignore` 必须含 `.env*`(vercel deploy 上传遵循 .vercelignore 而非 .gitignore,默认模板已含)。

## 10. 关闭部署保护(生产端点必须公开可达)

控制台:`https://vercel.com/<团队>/eve-software-factory-template/settings/deployment-protection`

把 **Vercel Authentication → Require Log In** 取消勾选并 Save。应用层自带 OIDC 门禁(`agent/channels/eve.ts` 会拒绝公开浏览器流量),生产在 Vercel 层公开是这套架构的预期形态。

> 坑 ⑩:关掉后 **302 不会立刻消失**,边缘传播要等几分钟;别急着判定失败。验证:匿名 `curl -o NUL -w "%{http_code}" https://<生产域名>/` 从 `302`(跳 vercel.com/sso-api)变为非 302(200/401 均可,应用层正常应答)。
> 诊断口诀:**302 = Vercel 层保护;401/正常 JSON = 应用层鉴权(符合预期)**。

## 11. 终验:无人值守流水线

```powershell
gh label create factory --repo <你的用户名>/factory-playground --color 5319e7
gh issue create --repo <你的用户名>/factory-playground --title "Add hello.txt" --body "Create hello.txt at repo root containing: hello world"
gh issue edit <issue号> --repo <你的用户名>/factory-playground --add-label factory
```

预期时序:几分钟内 issue 出现机器人首条评论("Picked this up. Classification is done..."),同时分类结果镜像为仓库原生标签;随后 analyst/implementer/reviewer 依次执行;终点是关联该 issue 的**草稿 PR**(正文含 What this does / Why this approach / 验收判定)。

**如果静默超过 10 分钟**,按此顺序定位:

| 检查点 | 位置 | 判读 |
|------|------|------|
| GitHub 发没发事件 | App 设置 → Advanced → Recent Deliveries | 无 `issues.labeled` 记录 → 事件订阅缺失(坑 ⑥) |
| 事件投递响应 | 同上,点开看颜色/状态码 | 302/红 → 部署保护(坑 ⑩);200 但无反应 → trigger 目的地配置(坑 ⑤) |
| 函数层有没有收到 | `vercel logs <部署URL>` | "No logs found" → 请求没到达 |
| 机器人行为 | issue 页 | 有评论 → 流水线已活 |

## 附:本次实录踩坑总表(症状 → 根因 → 解法)

| # | 症状 | 根因 | 解法 |
|---|------|------|------|
| ① | `vercel : 无法将...识别为 cmdlet` | CLI 未安装 | `npm install -g vercel` |
| ② | `Failed to connect <repo> to project` | GitHub App 无仓库访问权(git 集成步) | B 路线可忽略;要修则装 App 后 `vercel git connect` |
| ③ | FACTORY_REPO 校验失败/值怪异 | PS 5.1 管道传值前置 BOM | 文件重定向:`cmd /c "vercel env add ... < file"` |
| ④ | `eve info` 报环境变量缺失 | 它不读 .env.local,读 shell | validate 前 `$env:` 注入三变量 |
| ⑤ | webhook 全发去 `D:/soft/Git/eve/v1/github` | Git Bash MSYS 路径转换 | PowerShell 跑;或 `MSYS_NO_PATHCONV=1` 前缀;事后删错误目的地 |
| ⑥ | 打标签无任何反应,投递记录无 issues | App 只订阅了 Pull request | Permissions & events 补勾五项 |
| ⑦ | `OAuth application name cannot use the word Linear` | Linear 品牌保护 | 名字去掉 Linear 字样 |
| ⑧ | `MODEL_CALL_FAILED: model did not return a response` | baseURL 缺 `/v1`(SDK 约定差异 + 网关 200 空流) | baseURL 以 `/v1` 结尾 |
| ⑨ | `Cannot compile agent compaction ...` | 网关目录无该模型元数据 | 六个 agent.ts 加 `modelContextWindowTokens` |
| ⑩ | 生产域名匿名 302 → sso-api | Vercel Authentication 开着 + 传播延迟 | 关 Require Log In,等几分钟再验 |

- 【已修复 2026-10-11】implementer 曾偶尔不按 `factory/` 前缀命名分支(如 `feat/hello-txt`、`chore/add-hello-txt`),导致红 CI 自动修复环(只认 `factory/*`)不接手。修复为三层:`validateBranch` 现结构性拒绝 `factory/` 前缀外的分支名(push_branch / checkout_branch 共用,报错信息直接给出正确格式);git 工具描述与入参描述内联前缀要求(插值 `FACTORY_BRANCH_PREFIX`,随 env 覆盖自动同步);implementer 指令改 MUST 措辞并注明"计划建议了别的分支名也照 `factory/` 形式切",analyst 指令禁止在计划中指定分支名。注意:历史遗留的非 `factory/` 分支工厂不再能 fetch,属预期
