# 自托管工厂运维手册(M1-M4 落地态,2026-11-01)

> 服务对象:zjordon/examination-system(经 GitHub App zjordon-foreman-local);宿主:专用 Ubuntu 24.04 机(192.168.5.7)。细节档案:docs/implement-plan/M1~M4、docs/architecture.md §2.8/2.9。

## 一、常驻布局

| 组件 | 守护 | 端口/入口 | 自启 |
|------|------|------|------|
| 工厂服务 foreman-local | pm2(systemd pm2-jasonzhang) | 0.0.0.0:3000;公网 https://factory.zjordon.com | ✓(pm2 resurrect,开机实测 9 秒回归) |
| cloudflared 隧道 | systemd cloudflared | factory.zjordon.com → localhost:3000 | ✓(域名 health 实测 28-33 秒回 200) |
| 每日备份 | 用户 crontab 03:17 | tar → /data/factory-backup(14 份轮转) | ✓ |
| health 拨测 | GitHub Actions(health-probe.yml,在 examination-system) | 每 30 分钟,失败走 GitHub 邮件 | ✓ |
| CI(ruff+pytest+e2e) | GitHub Actions(ci.yml,同上) | push/PR 全触发 | ✓ |

## 二、日常操作

- **派活**:examination-system 开 issue 打 `factory` 标签(无人值守全流程);@zjordon-foreman-local 评论(受信者,有人值守语义)
- **看进度**:issue 线程的机器人评论;`pm2 logs foreman-local`;`docker ps | grep eve-sbx`
- **状态探针**:`curl http://127.0.0.1:3000/eve/v1/health`(本机)/ `curl https://factory.zjordon.com/eve/v1/health`(全链)
- **升级工厂代码**:`git pull` → `pnpm install` → `pnpm build` → `pm2 restart foreman-local` → `pm2 save`
- **升级站点镜像**:改 `agent/sandbox/Dockerfile` → `docker build -t foreman-station:<N+1> agent/sandbox/` → 改 `agent/lib/github/repo-sandbox.ts` 的 STATION_IMAGE → `pnpm build` → restart → save。**标签进位会自动轮转三站模板**(显式镜像引用进 options 哈希)
- **env 变更(坑)**:`.env.local` 改后 **pm2 delete + 干净 shell 全新 start + pm2 save**——`--update-env` 清不净 dump 里捕获的旧 env;`FACTORY_SETUP_COMMAND` 等含空格值必须加引号

## 三、断电/断网 SOP(M4-T4 实测口径)

- **自动回归**:开机后无需人工——pm2 9 秒起、health 20 秒 200、域名链路 28-33 秒 200(两次实测一致);docker 为 socket 激活,首个沙箱使用时唤起
- **在途轮次的结局**:进程被 SIGKILL,**无声死亡**——无错误评论、无收尾,issue 线程停在最后一条站点评论;被杀站点的容器留 Exit(137) 尸体(状态在容器文件系统里,可 docker start 查尸)
- **复活**:受信者在 issue 里 @zjordon-foreman-local 评论(如「断电恢复,请继续/重跑本任务」)→ 新会话带着线程历史(含已完成的分析)重推;实测派发 30 秒级
- **告警面**:若断电跨越拨测窗口(30 分钟粒度),GitHub 会发 Run failed 邮件——恢复后无需手动消警,下个周期自动回绿

## 四、备份与恢复

- 备份内容:`.eve/.workflow-data`(会话/轮次状态)+ `.eve/blob-data`(偏好/工厂大脑/工件);脚本 `scripts/backup-factory-data.sh`(tar 完整性门 + 14 份轮转),日志 `/data/factory-backup/backup.log`
- 恢复:`tar -xzf /data/factory-backup/factory-data-<stamp>.tar.gz -C <目标>` 后结构核验(blob 文件数、大脑文件与在线比对);深读变体:`FACTORY_DATA_DIR=<恢复副本>` 起 dev 冒烟
- 活照快照语义:备份时在途轮次的实时写入可能部分入包(实测差 ~1000/137k 文件),属预期

## 五、巡检与清理(周期性,或盘紧时)

- `scripts/patrol-containers.sh`(报告)/ `--prune`(清理 exit>24h 的 eve-sbx 孤儿容器,运行中与模板镜像永不碰)
- 旧模板镜像:站点容器退役后 `docker image prune -a` 回收(eve-sandbox-template 多世代累积,现 ~2.07GB/世代)
- 已知噪音(非故障):glm-5.3 maxOutputTokens 4096 告警、strict-mode 忽略告警、通道 sandbox checkout swallowed(Docker 后端预期)
- 已知风险:examination-system 自有 flaky e2e(test_mobile_viewport 计分断言 + answer_detail 竞态,CI 约五成概率触发)——工厂修复环会消耗 2 次尝试后停手交人,修 flaky 需排期

## 六、eval 基线与夹具

- `pnpm eval --tag fast` 基线:6/7 用例 45/46 gates(judge gate 走网关,本地零网关形态预期损失)
- ship-gate 用例前置「目标仓最新 open PR 须为 draft」:随工厂自然产出维持(examination-system 常态有 draft PR);**全部转正合并后需补一个 trivial draft**,否则该用例失前置

## 七、隔离铁律(不可破)

- 任一时刻一个仓库只有一个工厂 App;切仓 = 卸旧装新(分钟级可逆)
- main(feat/self-hosting 的上游)为云端冻结形态,不从自托管分支部署;云端 A/B 无动作
- App 安装范围显式只选目标仓;GitHub App 私钥与 webhook secret 不入仓不入会话
